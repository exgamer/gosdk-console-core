# Changelog

## [1.2.0]

Публичный API не менялся; код сервисов компилируется без правок.

### Добавлено

- Сквозной CorrelationID: контекст команды (`cmd.Context()`) несёт id корреляции запуска (`sdkctx.CorrelationID`,
  gosdk-core) — новый на каждый запуск, если в контексте приложения его нет. Требуется gosdk-core v1.3.0.

### Исправлено

- `errorreporter.Flush` — на любом пути выхода из команды (успех, ошибка, паника); раньше — только при ошибке.
- Паника в коде команды (`RunE`, `Run`, хуки) перехватывается: событие уровня `fatal` с тегом команды и
  стеком (`Extra["panic"]`), `Start`/`RunAll` возвращает ошибку `console command <имя> panic: ...`. Раньше
  паника роняла процесс без события в Sentry.
- Контекст команды (`cmd.Context()`) отменяется по `SIGINT`/`SIGTERM`; после первого сигнала обработка
  сигналов возвращается к умолчанию — второй завершает процесс.
- Ошибки разбора аргументов cobra (неизвестная команда или флаг, неверное число аргументов, не задан
  обязательный флаг) не отправляются в Sentry — возвращаются как раньше.

### ⚠️ Изменения поведения

- Опечатка в имени команды или флаге больше не создаёт событие в Sentry; `RunAll` возвращает ту же ошибку.
- Паника в команде не роняет процесс: `RunAll` возвращает ошибку — код выхода задаёт вызывающий код
  (`log.Fatal(err)` в примере README — по-прежнему `exit 1`).
- `SIGINT`/`SIGTERM` во время команды не убивают процесс сразу, а отменяют `cmd.Context()`. Команда, которая
  не проверяет контекст, доработает до конца; прервать её — вторым сигналом.
- Чтобы отличать ошибку кода команды от ошибки разбора аргументов, `Start` один раз оборачивает `RunE`,
  `PreRunE`, `PostRunE`, `PersistentPreRunE`, `PersistentPostRunE` зарегистрированных команд: после `Start`
  эти поля команд содержат обёртки (поведение команды то же).
